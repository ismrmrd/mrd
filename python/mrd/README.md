Version-agnostic ("dynamic") binary reader for the yardl-generated MRD format.

The yardl binary format embeds the full schema JSON in every file, and the
generated ``BinaryMrdReader`` rejects any file whose embedded schema does not
exactly match the schema compiled into this library, invalid schema error. Schema
evolution exists for cpp, 

``DynamicMrdReader`` instead *constructs its serializers from the schema
embedded in the file*, then reconciles the decoded values field-by-NAME onto
the CURRENT model. Old files are never rewritten; this is backward
compatibility only (old file + new reader).

It relies on four schema-evolution invariants, which must hold between the
file's version and this library's version:
  1. Union variants are append-only (never inserted or removed)
  2. Fields are never renamed
  3. New fields are always optional (T?)
  4. Protocol steps are never reordered or removed

Under these invariants every reconciliation case is deterministic and
lossless: a field present in the file but gone from the model is decoded and
discarded; a field added since the file was written is absent from the file
and defaults to ``None`` (invariant 3); union tag bytes line up because the
file's variant order is a prefix of the model's (invariant 1).

NOTE: this only handles backward-compatible evolution. It does not, and
cannot, invent data for genuinely incompatible layout changes. For those, use
the explicit layout-aware tooling in ``mrd.tools.upgrade``.

This module is hand-written (unlike ``binary.py``, which is generated by
yardl) so it survives regeneration.
